The Four Goals of Cryptography

Confidentiality

Ensures data remains private and is only seen by authorized parties.

Integrity

Ensures that data has not been altered or tampered with in transit.

Authentication

Verifies the identity of the sender and receiver of the information.

Non-repudiation

Provides proof that a sender actually sent a message, preventing them from denying it later.

Symmetric vs. Asymmetric Encryption

Symmetric (Shared Secret)

  • Uses a single key for both encryption and decryption.
  • Extremely fast; ideal for bulk data encryption (e.g., AES).
  • Major Weakness: How do you securely share the secret key in the first place? (Key exchange problem).
  • Provides confidentiality only.

Asymmetric (Public Key)

  • Uses a key pair: a public key to encrypt and a private key to decrypt.
  • Very slow compared to symmetric encryption (e.g., RSA).
  • Major Strength: Solves the key exchange problem; you can share your public key openly.
  • Provides confidentiality, integrity, authentication, and non-repudiation.

Hybrid Approach: Most systems (like TLS/SSL) use slow asymmetric encryption to securely exchange a fast symmetric key for the actual communication session.

Common Encryption Algorithms

Symmetric

  • AES (Advanced Encryption Standard): The modern standard for bulk encryption, using key sizes of 128, 192, or 256 bits.
  • DES/3DES: Older, deprecated standards. No longer considered secure.

Asymmetric

  • RSA: The original public key algorithm, based on the difficulty of factoring large prime numbers.
  • ECC (Elliptic Curve Cryptography): A more modern approach that provides the same level of security as RSA with much smaller key sizes, making it ideal for mobile and low-power devices.

Hashing: The Digital Fingerprint

A hash function takes an input of any length and produces a unique, fixed-length output (the "hash" or "digest"). It's a one-way process; you can't reverse it to get the original input.

Key Properties

  • Integrity: Changing even one bit in the input file will produce a completely different hash. This is how we verify file integrity.
  • Collision Resistant: It should be computationally impossible to find two different inputs that produce the same hash.

Common Algorithms

MD5 (broken), SHA-1 (deprecated), and SHA-256 (current standard).

Digital Signatures: How They Work

Digital signatures combine hashing and asymmetric cryptography to provide integrity, authentication, and non-repudiation.

Signing a Message

  1. Create a hash of the original message.
  2. Encrypt that hash with your private key. This encrypted hash is the signature.
  3. Send the original message + the signature.

Verifying a Signature

  1. Create a new hash of the received message.
  2. Decrypt the received signature with the sender's public key to reveal the original hash.
  3. If the two hashes match, the signature is valid.

🤔 Think-Pair-Share: Key Selection

Scenario

Alice wants to send a confidential message to Bob. She also wants Bob to be sure the message truly came from her and was not altered.

Your Task (5 minutes)

  • To sign the message (prove it's from her), which key does Alice use?
  • To encrypt the message (make it confidential), which key does Alice use?
  • To verify Alice's signature, which key does Bob use?
  • To decrypt the message, which key does Bob use?

Public Key Infrastructure (PKI)

PKI is the framework of hardware, software, policies, and procedures required to create, manage, distribute, use, store, and revoke digital certificates.

Digital Certificate (X.509)

An electronic document that binds a public key to an identity (a person, a server) and is signed by a trusted third party.

Certificate Authority (CA)

The trusted third party that issues digital certificates. Your browser has a built-in list of trusted CAs.

The Chain of Trust

Your browser doesn't trust a website's certificate directly. It trusts the CA that signed it. This creates a "chain of trust."

Certificate Revocation

What happens if a private key is stolen? The CA must revoke the certificate.

Certificate Revocation List (CRL)

A "blacklist" of revoked certificate serial numbers published by the CA. Browsers must periodically download this large list, which can be slow and inefficient.

Online Certificate Status Protocol (OCSP)

A real-time protocol. The browser sends a request to the CA's server asking for the status of a specific certificate. It's more efficient but can cause performance bottlenecks and privacy concerns.

Certificate Formats

PEM (.pem, .crt)

ASCII (text-based) format. Often starts with `-----BEGIN CERTIFICATE-----`.

DER (.der, .cer)

A binary format of the certificate. Windows often uses this.

PFX/P12 (.pfx, .p12)

A binary format that can contain the entire certificate chain and, optionally, the private key.

P7B (.p7b)

An ASCII format that contains certificates and the chain, but not the private key.

Obfuscation: Steganography

The art of hiding secret messages within an ordinary, non-secret file (like an image, audio, or video file) to conceal its existence.

How it Works

Steganographic algorithms make alterations to the least significant bits (LSBs) of the data that makes up an image or audio file. These changes are so minor that they are imperceptible to the human eye or ear, but can be extracted with the right tool and key.

Real-World Use Case: Digital Watermarking

A hidden copyright notice embedded in an image is a form of steganography used to protect intellectual property.

Cryptographic Attacks (Part 1)

Birthday Attack

A brute-force attack against hash functions. Based on the "birthday paradox," which shows that it's statistically much easier to find two random inputs that generate the same hash (a collision) than it is to find an input that generates a specific, predetermined hash.

Collision Attack

The specific goal of a birthday attack. The attacker seeks to find any two different messages that produce the exact same hash value. A successful collision undermines the integrity guarantees of a hashing algorithm.

Cryptographic Attacks (Part 2)

Downgrade Attack

An on-path attacker intercepts a connection and forces the two parties to negotiate a weaker, less secure version of a protocol (like an old version of TLS) that the attacker knows how to break.

Replay Attack

An attacker captures a valid data transmission (e.g., a login session with a cookie) and re-transmits it later to impersonate the legitimate user. This is why anti-replay mechanisms like timestamps and sequence numbers are crucial.

Cryptographic Attacks (Part 3)

Weak Implementations

Using a strong algorithm (like AES) but implementing it incorrectly. A famous example is the WEP protocol, which used the RC4 stream cipher in a way that made the keys easily crackable.

Improper Key Management

The root cause of many breaches. This includes hard-coding keys in software, reusing keys across multiple systems, or failing to protect private keys, making the entire cryptographic system worthless.

Advanced & Emerging Concepts

Blockchain

A distributed, immutable public ledger. It stores records in a way that prevents tampering, forming the basis for cryptocurrencies like Bitcoin.

Homomorphic Encryption

A cutting-edge form of encryption that allows computation to be performed on ciphertext, generating an encrypted result which, when decrypted, matches the result of operations performed on the plaintext.

Post-Quantum Cryptography (PQC)

New cryptographic algorithms that are secure against attacks from both classical and future quantum computers. NIST is standardizing algorithms like CRYSTALS-Kyber (for key exchange) and CRYSTALS-Dilithium (for digital signatures) to prepare for this future threat.

Chapter Summary

Cryptography Provides Four Goals

Confidentiality, Integrity, Authentication, and Non-repudiation are the pillars of secure communication.

Use the Right Tool for the Job

Symmetric crypto is for speed and bulk encryption. Asymmetric crypto is for key exchange and digital signatures.

PKI Enables Trust at Scale

The Public Key Infrastructure, built on Certificate Authorities and a chain of trust, is what allows secure communication across the global internet.

🚨 Bottom Line

Modern security is built on a hybrid model that uses the strengths of each cryptographic primitive to create a secure, scalable, and trustworthy system.
