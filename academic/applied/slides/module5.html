Vulnerability Scanning

Credentialed vs. Non-Credentialed

Non-Credentialed: Sees what an external attacker sees. Faster, but more prone to false positives.

Credentialed: Logs into the system with read-only rights. More accurate and detailed, but requires more setup.

Intrusive vs. Non-Intrusive

Non-Intrusive: A safe scan that only checks for vulnerabilities without trying to exploit them.

Intrusive: Attempts to exploit a vulnerability to confirm it. More accurate, but carries a risk of disrupting or crashing the target system.

🚨 Real-World Example: Log4Shell (CVE-2021-44228)

This critical vulnerability in the widespread Log4j logging library allowed for unauthenticated remote code execution. Vulnerability scanners were crucial for organizations to quickly identify all affected systems across their networks, demonstrating the need for comprehensive, credentialed scanning to find vulnerable software versions.

Prioritizing with CVSS

The Common Vulnerability Scoring System (CVSS) provides a standardized way to rate the severity of vulnerabilities.

Key Metrics

  • Attack Vector (AV): How is it exploited? (Network, Local)
  • Attack Complexity (AC): How hard is it to exploit? (Low, High)
  • Privileges Required (PR): Does the attacker need an account?
  • Impact (C, I, A): What is the impact on Confidentiality, Integrity, and Availability?

Severity Rating Scale

  • 9.0 - 10.0: 🔥 Critical
  • 7.0 - 8.9: 🔶 High
  • 4.0 - 6.9: 🟡 Medium
  • 0.1 - 3.9: 🟢 Low

Penetration Testing: Thinking Like an Attacker

A pen test is an authorized, legal attempt to defeat security controls to find exploitable flaws before real attackers do.

⚪ White Box

Testers have full knowledge: source code, diagrams, credentials. Best for a deep, thorough test.

⚫ Black Box

Testers have zero prior knowledge. Best for simulating a real external attacker.

🔘 Gray Box

A mix of both. Testers might have user-level credentials to simulate an insider threat.

Penetration Test Types

Physical

Identifies and exploits vulnerabilities in physical controls like locks, fences, and access control systems to gain unauthorized access to facilities.

Offensive

Proactively simulates real-world cyberattacks to exploit vulnerabilities in networks, systems, and applications (the "Red Team").

Defensive

Focuses on evaluating the effectiveness of security policies and technologies in detecting and mitigating threats (the "Blue Team").

Integrated

Combines offensive and defensive testing ("Purple Teaming") to provide a comprehensive assessment of security posture through active collaboration.

Threat Hunting: The Proactive Search

Threat hunting uses the attacker mindset to search for evidence of successful attacks that have already bypassed preventative controls.

Core Philosophy: "Presumption of Compromise"

This approach assumes that attackers are already inside the network. The goal is not to prevent a breach, but to find and remove attackers before they can achieve their objectives.

Process: Intelligence Fusion

Hunters combine information from threat feeds, security bulletins, and other sources to form hypotheses about potential attacker activity, then search for that evidence in logs and network traffic.

Pen Test Process

📜 Rules of Engagement (RoE)

The most important document! It's the contract that defines:

  • Scope: What is in-bounds and out-of-bounds?
  • Timeline: When can testing occur?
  • Permission: The "Get Out of Jail Free" card.
  • Communication Plan: Who to call if something breaks.

Audits vs. Assessments

🛡️ Security Assessment

A comprehensive review to identify vulnerabilities and recommend improvements. Can be done by an internal team. The goal is to get better.

⚖️ Security Audit

A formal examination by an independent third party to demonstrate compliance with a standard (e.g., ISO 27001, PCI DSS). The goal is to prove security to others.

The key output of an audit is an attestation: a formal statement from the auditor that the controls are adequate and effective.

Chapter Summary

🔄 Testing is a Cycle, Not a One-Time Event

Effective security requires a continuous cycle of vulnerability identification, analysis, remediation, and validation.

🎯 Know Your Goal

Use the right tool for the job. Vulnerability scans find known issues. Pen tests find exploitable pathways. Audits prove compliance.

💯 Prioritization is Key

You can't fix everything at once. Use CVSS and business context to focus on the vulnerabilities that pose the greatest risk to your organization.

🚨 Bottom Line

Security assessment isn't just about finding flaws; it's about building a resilient program that continuously learns and improves its defenses.
