Introduction to Networking Fundamentals

From Physical Addresses to Digital Handshakes

Core concepts for understanding how devices communicate.

Every Device Needs Two Addresses

1. The Physical Address (MAC)

Like a person's unique, unchangeable fingerprint. It identifies the actual hardware device.

2. The Logical Address (IP)

Like a home's mailing address. It's assigned based on your location and can change if you move to a new network.

You need both to communicate: one to find the right house on the street (IP), and one to hand the letter to the right person inside (MAC).

MAC Addresses

  • Stands for: Media Access Control address.
  • Purpose: Uniquely identifies a device's network hardware (like a Wi-Fi card or Ethernet port) on a local network.
  • Permanent: It's "burned in" by the manufacturer and doesn't change.
  • Format: A 12-digit hexadecimal number, often written like this:
    00:1A:2B:3C:4D:5E

IP Addresses

  • Stands for: Internet Protocol address.
  • Purpose: Identifies a device's location on a network, allowing it to communicate with devices on other networks (like the internet).
  • Temporary: It's assigned by the network you connect to (e.g., your router) and changes when you join a new network.
  • Format: A set of four numbers, each from 0 to 255, like this:
    192.168.1.101

Connecting Local Devices with ARP

If IP is for global and MAC is for local, how do they work together?

Address Resolution Protocol (ARP)

ARP is the translator for a local network. It answers one simple question:

"I have this IP address (192.168.1.50), but I need to deliver this data locally. Who on my network has this IP, and what is your MAC address?"

Your computer sends an "ARP request" to everyone on the local network. The device with that IP address replies with its MAC address. Now, communication can happen!

Gateways Connecting Networks

How does data leave your local network to get to the internet?

The Role of a Gateway

A gateway (usually your router) is the single exit and entry point for your local network.

  • It connects your private local network to other networks, like the internet.
  • When you want to visit a website, your computer sends the data to the gateway.
  • The gateway then forwards that data onto the internet on your behalf.

Sharing Connections with NAT

How can your phone, laptop, and TV all share one internet connection?

Network Address Translation (NAT)

NAT is a clever trick performed by your gateway (router) that lets many devices share a single public IP address.

It translates the private IP addresses of your devices (192.168.1.101) into your home's single public IP address when sending data out, and vice-versa for incoming data.

The Internet Journey: Hops and Routing

Your data doesn't go straight to its destination. It takes a trip, hopping between many routers.

  • Hops: Each router your data passes through on its way to the destination is called a "hop".
  • Routing: Each router (or gateway) makes a decision. It looks at the destination IP address and checks its routing table to find the best path for the next hop.
  • Internet Backbone: Routers talk to each other to share information, forming massive, high-speed networks that act as the superhighways of the internet.

DNS: The Internet Phonebook

How does your computer know that `www.google.com` is `142.250.197.132`?

Domain Name System (DNS)

DNS translates human-readable domain names (like google.com) into computer-readable IP addresses.

  • Humans remember names; computers understand numbers. DNS bridges that gap.
  • When you type a website, your computer asks a DNS server for the IP address first.

Reliable Conversations with TCP

Transmission Control Protocol (TCP)

Once we know where to send data, how do we make sure it gets there without errors?

  • ✓Connection-Oriented: TCP establishes a dedicated connection before any data is sent.
  • ✓Reliable Delivery: It guarantees that all data packets arrive, and in the correct order. If a packet is lost, TCP resends it.

The process of setting up this reliable connection is called the Three-Way Handshake.

The Three-Way Handshake

This is how two devices start a TCP conversation. It's like a polite phone call.

1. SYN

Client says: "I'd like to synchronize with you."

↓
2. SYN/ACK

Server replies: "I acknowledge your request and I'd also like to synchronize with you."

↓
3. ACK

Client says: "I acknowledge your reply. The connection is established!"

Key Takeaways

Local Network (LAN)

MAC for hardware, IP for local location, ARP to link them.

Leaving the Network

The Gateway is the exit. NAT lets all devices share one public IP address.

Internet Journey

Data travels in hops between routers, which use routing tables to find the best path. DNS translates names to destination IPs.

Reliable Connection

TCP ensures data arrives correctly, starting with the three-way handshake.
