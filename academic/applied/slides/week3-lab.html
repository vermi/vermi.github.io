Part 1: File Integrity

What is it?

File integrity is the assurance that a file has not been altered, corrupted, or tampered with in any unauthorized way. It's about trusting that the file you have today is the exact same file that was created yesterday.

Why does it matter?

Software Downloads

Ensuring the installer you downloaded hasn't been modified to include malware.

Forensic Evidence

Proving that a piece of digital evidence has not been changed since it was collected.

System Files

Detecting if an attacker has modified critical OS files to create a backdoor.

The Digital Fingerprint: Hashing

We verify integrity using a cryptographic hash function. This is a mathematical algorithm that takes any input file and produces a unique, fixed-length string of characters.

Changing even one bit in the input file will produce a completely different hash.

Common Hashing Algorithms

MD5

128-bit hash. Considered broken and insecure for cryptography. Avoid for security purposes.

SHA-1

160-bit hash. Also cryptographically broken, but its speed makes it common in non-critical systems like Git version control. We will use `sha1sum` in the lab.

SHA-256 (and SHA-2 family)

256-bit hash. The current industry standard for security. Strong, secure, and widely supported.

How to Check File Integrity

The process is simple: generate a hash of the file you have, and compare it to the known-good hash provided by the source.

$ sha256sum important_file.zip

e3b0c442...b855 important_file.zip

$ sha1sum important_file.zip

da39a3ee...5e2799b6 important_file.zip

If the hashes match EXACTLY, the file is intact.

If they are DIFFERENT, the file is corrupt or has been tampered with.

Automated Monitoring with AIDE

What is AIDE?

AIDE (Advanced Intrusion Detection Environment) is a tool that automates file integrity checking. Instead of manually checking one file at a time, AIDE monitors thousands of important system files for any changes.

How it Works

1. Initialization

AIDE scans your system and creates a baseline database containing the hashes and other attributes of every important file.

2. Checking

Later, you run AIDE again. It re-scans the system and compares the current state of files to the baseline, reporting any additions, deletions, or modifications.

Part 2: System Call Tracing

What is a System Call?

A system call (syscall) is a request made by a program to the operating system's kernel for a service. Applications can't just access hardware directly; they must ask the kernel to do it for them.

Your Program

👨‍💻

(User Space)

"Please open this file!"

[ System Call ]

↕

OS Kernel

🛡️

(Kernel Space)

Common tasks requiring syscalls: opening/reading files, creating processes, sending network packets, accessing hardware.

Why Trace System Calls?

By watching the syscalls a program makes, we can understand its true behavior, regardless of what the code looks like.

🐛 Debugging

  • Find out why a program is crashing.
  • See which files a program is trying (and failing) to open.
  • Understand performance bottlenecks.

🔬 Security Analysis

  • Detect if a program is trying to access sensitive files (e.g., `/etc/shadow`).
  • See if malware is opening network connections to a C&C server.
  • Identify unexpected or suspicious behavior.

Introducing `strace`

strace is a powerful command-line tool for Linux that intercepts and records the system calls made by a process and the signals it receives. It's an essential tool for system administrators and security analysts.

$ strace ls

execve("/usr/bin/ls", ["ls"], 0x7ffc12a4b5f8 /* 22 vars */) = 0

brk(NULL) = 0x55c1b2a9d000

...

openat(AT_FDCWD, "/etc/ld.so.cache", O_RDONLY|O_CLOEXEC) = 3

...

openat(AT_FDCWD, ".", O_RDONLY|O_NONBLOCK|O_CLOEXEC|O_DIRECTORY) = 3

getdents64(3, /* 10 entries */, 32768) = 288

write(1, "file1.txt\nfile2.log\n", 20) = 20

close(3) = 0

...

exit_group(0) = ?

The output shows every interaction the `ls` command had with the kernel to list the files in the current directory.

Key Takeaways

Manual vs. Automated Integrity

Use sha1sum for single file checks and aide for continuous system-wide monitoring.

Hashing is the How

Cryptographic hashes create a unique fingerprint to verify integrity. SHA-256 is the current secure standard.

Syscalls are the Bridge

System calls are how programs ask the OS kernel to perform actions.

`strace` is the Magnifying Glass

The strace tool lets you observe these syscalls to understand a program's true behavior.
