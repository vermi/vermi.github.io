Network Security Design

Attack Surface Management

  • Minimize exposed services and entry points
  • Strategic device placement based on trust levels
  • Balance between security and operational requirements

Security Zones

  • Trusted: Internal network with authorized users
  • Untrusted: External networks (Internet)
  • Restricted: High-value assets requiring extra protection

Connectivity & Failure Modes

  • Fail-open: Allows traffic when security fails (availability priority)
  • Fail-closed: Blocks traffic when security fails (security priority)

Network Segmentation

Core Principle:

Divide networks into smaller segments to contain breaches and control traffic flow

VLANs

  • Logical separation at Layer 2
  • Segment by department or function
  • Requires Layer 3 for inter-VLAN routing
  • Cost-effective segmentation

Screened Subnet (DMZ)

  • Buffer between trusted/untrusted networks
  • Hosts public-facing services
  • Protected by two firewalls
  • Limits internal exposure

Physical vs. Logical Isolation

  • Physical: Air-gapped networks, separate hardware (highest security)
  • Logical: VLANs, subnets, access controls (flexible, cost-effective)

Zero Trust Architecture

"Never Trust, Always Verify"

Control Plane

  • Adaptive Identity: Continuous authentication
  • Threat Scope Reduction: Limit blast radius
  • Policy-Driven Access: Dynamic decisions
  • Policy Engines: Centralized control

Data Plane

  • Subjects/Systems: Users and devices
  • Policy Enforcement Points: Gateways
  • Implicit Trust Zones: Microsegmentation

2025 Adoption: 60% of organizations use Zero Trust ($34.50B market). Federal agencies mandated by executive order.

Network Access Control (NAC)

Purpose:

Control device access based on identity, posture, and compliance

802.1X Authentication

  • Supplicant: Device requesting access
  • Authenticator: Switch/AP enforcing access
  • Auth Server: RADIUS validation
  • Port-based access control

NAC Capabilities

  • Device posture assessment
  • Health checks (patches, AV)
  • Quarantine non-compliant devices
  • Dynamic VLAN assignment

EAP Methods

  • EAP-TLS: Certificate-based (most secure)
  • EAP-TTLS/PEAP: Tunneled with server cert
  • EAP-FAST: Cisco proprietary with PACs

Port Security Mechanisms (Part 1)

MAC Filtering

  • Limit allowed MAC addresses per port
  • Static, dynamic, or sticky learning
  • Violation modes: protect, restrict, shutdown

DHCP Snooping

  • Prevents rogue DHCP servers
  • Builds binding table (MAC-IP-VLAN-port)
  • Foundation for other security features

Loop Prevention

  • STP/RSTP: Spanning Tree Protocol
  • BPDU Guard: Disables ports receiving BPDUs
  • Prevents switching loops and storms

Broadcast Storm Prevention

  • Rate limiting on broadcast/multicast
  • Storm control thresholds
  • Protects network performance

Port Security Mechanisms (Part 2)

Dynamic ARP Inspection (DAI)

  • Validates ARP packets against DHCP snooping table
  • Prevents ARP spoofing attacks
  • Drops invalid ARP responses
  • Protects against man-in-the-middle attacks

IP Source Guard

  • Filters traffic based on DHCP snooping binding
  • Prevents IP address spoofing
  • Works at Layer 2 to verify source IP
  • Drops packets with invalid IP-MAC bindings

Virtual Private Networks (VPNs)

Purpose:

Create secure, encrypted tunnels over untrusted networks

IPSec VPN

  • Network layer (Layer 3) encryption
  • Transport: Encrypts payload only
  • Tunnel: Encrypts entire packet
  • Ideal for site-to-site connections

TLS/SSL VPN

  • Application layer encryption
  • Browser-based or client-based
  • More firewall-friendly (port 443)
  • Easier remote user deployment

Split-Tunnel

  • Only corporate traffic through VPN
  • Better performance, lower security

Full-Tunnel

  • All traffic routed through VPN
  • Higher security, potential performance impact

Network Security Appliances

Jump Server

  • Secure access point to critical systems
  • Centralized authentication and logging

Load Balancer

  • Distributes traffic across servers
  • High availability and SSL offloading

Proxy Server

  • Forward: Client-side filtering
  • Reverse: Server-side protection
  • Content filtering and caching

Web Filter

  • URL filtering and categorization
  • Blocks malicious sites

Data Loss Prevention (DLP)

  • Monitors sensitive data in motion, at rest, in use
  • Can block, quarantine, or alert on violations

Intrusion Detection & Prevention

IDS (Detection)

  • Passive monitoring and alerting
  • Out-of-band deployment
  • No network performance impact

IPS (Prevention)

  • Active blocking and prevention
  • Inline deployment
  • Can drop malicious packets

Detection Methods

  • Signature-based: Match known threats (low false positives)
  • Anomaly-based: Behavioral analysis (detects zero-days)
  • Heuristic: Rules-based suspicious behavior

NIDS/NIPS

  • Network-based deployment
  • Monitors network segments

HIDS/HIPS

  • Host-based agent deployment
  • Can see encrypted traffic

Firewall Technologies

Packet Filtering

  • Layer 3/4 filtering (IP, port, protocol)
  • Stateless (ACLs) or stateful
  • Fast but limited inspection

Stateful Inspection

  • Tracks connection state
  • Validates packets in session context
  • More secure than stateless

Web Application Firewall (WAF)

  • Layer 7 (application layer) protection
  • Protects against OWASP Top 10 (SQLi, XSS, CSRF)
  • HTTP/HTTPS request inspection

UTM

  • All-in-one security appliance
  • FW + IPS + AV + filter + VPN

NGFW

  • Deep packet inspection (DPI)
  • Application & identity awareness

Secure Network Protocols

Web & Transfer

  • HTTPS: HTTP + TLS (443)
  • SSH: Secure Shell (22)
  • SFTP: SSH File Transfer
  • FTPS: FTP + TLS (990)

Email & Directory

  • IMAPS: IMAP + TLS (993)
  • POP3S: POP3 + TLS (995)
  • SMTPS: SMTP + TLS (465/587)
  • LDAPS: LDAP + TLS (636)

Voice & Mgmt

  • SRTP: Secure RTP (VoIP)
  • SNMPv3: Secure SNMP
  • DNSSEC: DNS validation

Security Note: Always prefer encrypted variants over plaintext. Disable legacy protocols (Telnet, FTP, HTTP).

Email Security Mechanisms

SPF (Sender Policy Framework)

  • DNS TXT record listing authorized mail servers
  • Prevents sender address forgery

DKIM (DomainKeys Identified Mail)

  • Cryptographic signing of email messages
  • Verifies message integrity and authenticity
  • Public key in DNS, private key signs messages

DMARC (Domain-based Message Authentication)

  • Policy framework built on SPF and DKIM
  • Policies: none (monitor), quarantine, reject
  • Critical for preventing phishing and spoofing

DNS Security

DNSSEC

  • Cryptographic validation of DNS responses
  • Chain of trust from root to domain
  • Prevents DNS cache poisoning
  • Uses digital signatures (RRSIG)

DNS Filtering

  • Block access to malicious domains
  • Content categorization
  • Protects against phishing/malware
  • DNS sinkhole for threats

DNS over HTTPS (DoH) / DNS over TLS (DoT)

  • Encrypts DNS queries to prevent eavesdropping
  • DoH uses HTTPS (443), DoT uses port 853
  • Can bypass corporate DNS filtering (security concern)

2024 Threat: "Sitting Ducks" DNS hijacking compromised 70,000 domains via DNS misconfigurations.

On-Path Attacks (MITM)

Attack Methods

  • Attacker intercepts communication between two parties
  • Can eavesdrop, modify, or inject data
  • ARP Spoofing: Poison ARP cache to redirect traffic
  • SSL Stripping: Downgrade HTTPS to HTTP
  • Rogue Access Point: Fake Wi-Fi to capture traffic

2024 Example: Researchers demonstrated SSL stripping on Tesla charging stations, intercepting payment credentials.

Mitigations

  • Use HTTPS with HSTS, implement certificate pinning
  • Enable Dynamic ARP Inspection and port security
  • Educate users about rogue access points

DNS Attacks

DNS Hijacking

  • Compromise DNS server configuration
  • Redirect users to malicious sites
  • Can be at router, ISP, or registrar level
  • Difficult to detect by end users

DNS Poisoning

  • Inject false DNS records into cache
  • Exploits vulnerabilities in resolvers
  • Kaminsky attack (cache poisoning)
  • DNSSEC prevents this attack

Mitigations

  • Deploy DNSSEC for cryptographic validation
  • Monitor DNS traffic for anomalies
  • Use reputable DNS services
  • Implement DNS filtering and logging

DDoS Attacks

Objective:

Overwhelm target resources to deny service to legitimate users

Amplification Attacks

  • Exploit protocols with large responses
  • DNS: 28-54x amplification
  • NTP: Up to 556x amplification
  • Memcached: Up to 51,000x

Reflection Attacks

  • Spoof victim's IP as source
  • Reflectors send responses to victim
  • Obscures attacker's identity
  • Often combined with amplification

Other DDoS Types

  • Volumetric: Flood bandwidth (UDP/ICMP floods)
  • Protocol: Exhaust connection state (SYN flood)
  • Application Layer: Target services (HTTP floods, Slowloris)

2025: Q1 had 20.5M DDoS attacks (+358% YoY), peak 6.5 Tbps. Avg cost: $234K/incident.

DDoS Mitigation Strategies

Network Defenses

  • Rate limiting and traffic shaping
  • Ingress/egress filtering (BCP 38)
  • BGP FlowSpec for dynamic filtering
  • Anycast network distribution

Infrastructure Hardening

  • Over-provision bandwidth/capacity
  • Geographically distributed servers
  • Use CDNs for content delivery
  • Implement auto-scaling

Cloud-Based DDoS Protection

  • Scrubbing centers filter attack traffic
  • Massive capacity to absorb volumetric attacks
  • Examples: Cloudflare, Akamai, AWS Shield, Azure DDoS Protection

Credential Replay Attacks

Attack Method:

Capture and reuse valid credentials for unauthorized access

Common Scenarios

  • Session Hijacking: Steal tokens/cookies
  • Kerberos Replay: Reuse tickets
  • Pass-the-Hash: Use hash without cracking
  • Pass-the-Ticket: Reuse Kerberos tickets

Mitigations

  • Encryption: TLS/SSL for all auth traffic
  • Timestamps: Time-based validation
  • Nonces: One-time use tokens
  • Short TTLs: Expire sessions quickly
  • MFA: Multi-factor authentication

Deception Technology (Part 1)

Purpose:

Deploy decoy systems to detect, deflect, and gather intelligence on attackers

Honeypots

  • Decoy systems mimicking real servers
  • Low-interaction: Simulated services
  • High-interaction: Full OS and apps
  • No legitimate reason to access them

Honeynets

  • Network of interconnected honeypots
  • Simulates complete enterprise network
  • Observes lateral movement patterns
  • Provides richer intelligence

Deception Technology (Part 2)

Honeyfiles

  • Decoy files with enticing names
  • Monitor for unauthorized access
  • Examples: "passwords.xlsx", "customer_data.db"
  • Immediate alert when accessed

Honeytokens

  • Fake credentials embedded in systems
  • Canary tokens, fake API keys
  • Alert when used anywhere
  • Very low false positive rate

Benefits

  • Early warning system for breaches
  • Gather threat intelligence and TTPs
  • Waste attacker time and resources
  • Legal evidence collection

Software-Defined Networking (Part 1)

Core Concept:

Separate control plane from data plane for centralized management

SDN Architecture

  • Application Layer: Business logic
  • Control Layer: SDN controller (brain)
  • Infrastructure: Physical devices
  • APIs enable layer communication

Security Benefits

  • Centralized security policy enforcement
  • Dynamic microsegmentation
  • Automated threat response
  • Better visibility and monitoring

SD-WAN and SASE

SD-WAN (Software-Defined WAN)

  • Applies SDN principles to WAN connections
  • Intelligent routing across multiple links (MPLS, broadband, LTE)
  • Application-aware path selection
  • Built-in encryption and security
  • Cloud-first architecture for distributed enterprises

SASE (Secure Access Service Edge)

  • Converges SD-WAN and network security
  • Includes CASB, FWaaS, SWG, ZTNA
  • Cloud-native architecture
  • Delivers security at the edge, close to users
  • Ideal for remote workforce and cloud adoption

High Availability Architecture

Goal:

Ensure continuous operation through redundancy and fault tolerance

Redundancy Strategies

  • Active-Active: All nodes process traffic
  • Active-Passive: Standby on failure
  • Geographic Diversity: Multiple locations

Key Components

  • Redundant power (UPS, generators)
  • Multiple ISP connections
  • Clustered servers/databases
  • RAID for storage

Availability Metrics

  • 99.9% (Three nines): ~8.7 hours downtime/year
  • 99.99% (Four nines): ~52 minutes downtime/year
  • 99.999% (Five nines): ~5 minutes downtime/year

File Integrity Monitoring (FIM)

Purpose:

Detect unauthorized changes to critical files by monitoring attributes and contents

How FIM Works

  • Create baseline of file hashes
  • Periodically scan and compare
  • Alert on discrepancies
  • Uses cryptographic hashes (SHA-256)

Critical Files to Monitor

  • System binaries and libraries
  • Configuration files
  • Authentication databases
  • Web application code

Use Cases

  • Detect malware modifications
  • Compliance (PCI DSS, NIST)
  • Forensic investigation

Popular Tools

  • Tripwire, AIDE
  • OSSEC, Wazuh

Network Security Best Practices (Part 1)

Defense in Depth

  • Multiple layers of security controls
  • No single point of failure
  • Assume breach mentality
  • Complementary controls at each layer

Least Privilege

  • Grant minimum necessary access
  • Apply to users, processes, systems
  • Network micro-segmentation
  • Regular access reviews

Network Monitoring

  • Continuous traffic analysis
  • Centralized logging (SIEM)
  • Network flow analysis (NetFlow)
  • Baseline normal behavior

Configuration Management

  • Harden network devices
  • Disable unused services/ports
  • Keep firmware updated
  • Configuration backups

Network Security Best Practices (Part 2)

Security Operations

  • Regular vulnerability scanning and penetration testing
  • Incident response plan with defined procedures
  • Change management process
  • Security awareness training for network operations staff
  • Threat intelligence integration

Continuous Improvement

  • Regular security assessments and audits
  • Stay current with emerging threats
  • Update security controls as needed
  • Learn from security incidents
  • Participate in threat intelligence sharing
