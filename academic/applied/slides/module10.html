Cloud Service Models

Infrastructure as a Service (IaaS)

The provider offers fundamental building blocks: virtual servers, storage, and networking. You manage the OS, applications, and data.

Example: Amazon EC2, Microsoft Azure VMs

Platform as a Service (PaaS)

The provider manages the hardware and OS. You deploy and manage your applications on their platform.

Example: AWS Lambda (Serverless), Heroku

Software as a Service (SaaS)

The provider manages everything. You simply use the software, typically through a web browser.

Example: Google Workspace, Office 365

Cloud Deployment Models

Public Cloud

Resources are owned and operated by a third-party provider and shared among multiple tenants over the internet.

Private Cloud

Cloud infrastructure is operated exclusively for a single organization. It can be managed internally or by a third party.

Hybrid Cloud

A composition of two or more distinct cloud infrastructures (private, community, or public) that remain unique entities but are bound together.

Community Cloud

Infrastructure is provisioned for exclusive use by a specific community of consumers from organizations that have shared concerns.

The Shared Responsibility Model

Security in the cloud is a partnership. The provider is responsible FOR the cloud, while the customer is responsible FOR what they do IN the cloud.

IaaS

Provider: Secures the physical datacenter, hardware, and hypervisor.
You: Secure the OS, applications, network configuration, and data.

PaaS

Provider: Secures everything up to the OS/runtime.
You: Secure your application code and data.

SaaS

Provider: Secures almost everything.
You: Responsible for user access control and the data you put into the service.

Scenario: A Misconfigured S3 Bucket

A company uses Amazon S3 (an IaaS/object storage service) to store customer data. A developer accidentally configures the S3 bucket to be publicly readable by anyone on the internet, leading to a massive data breach.

  • What is one tool or process that could have prevented this misconfiguration?

Virtualization Concepts

Hypervisor

The software that creates and runs virtual machines (VMs). Type 1 (bare-metal) runs directly on hardware. Type 2 (hosted) runs as an app on an OS.

Containerization

Application-level virtualization (e.g., Docker). Packages an app and its dependencies into a container, which runs on a shared OS kernel. More lightweight than VMs.

Virtualization & Cloud-Specific Risks

VM Escape

An attacker breaks out of a guest VM and gains access to the host hypervisor or other VMs. This is a critical, high-impact vulnerability.

Resource Reuse

The cloud provider fails to properly wipe data from a de-provisioned resource (like a storage volume), and that data is exposed to the next customer who is assigned that resource.

Data Sovereignty

A legal principle stating that data is subject to the laws of the country in which it is located. Storing data in a global cloud provider's datacenter in a different country can create complex legal and compliance challenges.

Hardening Cloud Infrastructure

Security Groups / Network ACLs

Act as virtual firewalls for your instances to control inbound and outbound traffic. A fundamental network security control in the cloud.

Virtual Private Cloud (VPC)

A logically isolated section of the cloud where you can launch resources in a virtual network that you define, including public and private subnets.

Cloud Access Security Broker (CASB)

An intermediary that sits between users and cloud services to enforce security policies, monitor activity, and prevent data loss across multiple cloud platforms.

Infrastructure as Code (IaC)

The process of managing and provisioning infrastructure through machine-readable definition files (code), rather than manual configuration. Enables consistent, repeatable, and secure deployments.

Chapter Summary

Cloud is a Model, Not a Place

Understand the key characteristics (on-demand, scalable) and the different service (IaaS, PaaS, SaaS) and deployment (Public, Private) models.

Security is a Partnership

The Shared Responsibility Model is a critical concept. You are always responsible for your data, your user access, and your configurations.

Virtualization Introduces New Risks

Threats like VM escape are high-impact and unique to virtualized environments. Proper configuration and patching of the hypervisor is the provider's top priority.

🚨 Bottom Line

The cloud offers incredible flexibility, but its complexity can lead to simple misconfigurations that have massive security consequences. Always operate with a defense-in-depth mindset.
