The Teapot Trail

An Introduction to OSINT

Cybersecurity Mini-Lab · CYBS 0189

What is OSINT?

OSINT stands for Open-Source Intelligence.

It is the practice of collecting and analyzing information from publicly available sources to produce actionable intelligence. It is not hacking. Every source you touch today is a public record that anyone may read.

The key idea: nobody has to break anything for information to leak. Most of it was published on purpose, by someone who did not think about how it would look years later.

Why Does It Matter?

Defenders

Security teams run OSINT against their own organization to find what they are leaking — forgotten servers, exposed documents, stale contact info — before an attacker finds it first.

Attackers

Reconnaissance is step one of any attack. Names, email formats, software versions, and old infrastructure all help an attacker plan before they ever send a single packet.

Same sources. Same techniques. The difference is authorization and intent.

The Challenge

You will follow a trail through three stages. Each stage hands you the clue you need for the next one, so they must be solved in order.

It starts with a question:

A web server replies to your request with the status code 418 I'm a teapot.

Is that a real internet standard, or is someone messing with you?

Work on your own. Everything you need is in a browser. Roughly 5 minutes per stage.

STAGE 1 · FROZEN RECORDS

Who Decides What 418 Means?

HTTP status codes are not invented by whoever feels like it. One organization keeps the official list, and that list is public.

Go to the official registry and find the row for status code 418.

Start here: iana.org/assignments/http-status-codes/http-status-codes.xhtml

Clue: Use your browser's find function (Ctrl+F or Cmd+F) and search the page for 418. Read the Description column, then look at the Reference column next to it.

Your Flag: What does the official registry list as the description for status code 418?

STAGE 2 · THE ARCHIVE

Follow the Author

The registry pointed you at RFC 9110, which explains that 418 was a joke from an earlier document: RFC 2324, published on 1 April 1998.

Open RFC 2324 and scroll to the very end, to the section titled "Author's Address". It lists the author's email address. Try visiting that email's domain in your browser.

Start here: rfc-editor.org/rfc/rfc2324.txt

Clue: That domain is dead. It does not load, because the company behind it no longer exists under that name. A dead site is not a gone site — use the Wayback Machine to read it anyway.

Use this exact snapshot from 2004: web.archive.org/web/20041231090129/http://www.parc.xerox.com/

Your Flag: What was the full name of the research organization that owned that dead domain?

STAGE 3 · HIDDEN IN THE FILE

What the Document Admits

That same author still publishes his talks online. One of them is a presentation on the history of HTTP, saved as a PDF.

A file contains more than what you can see on the page. Inspect this document's metadata and read what software produced it.

The document: larrymasinter.net/071203-HTTPbis.pdf

Clue: Paste the PDF's link into the "Or enter a URL" box at extractmetadata.com, then look for the field named Producer.

No-tool alternative: open the PDF in Firefox, click the » button on the toolbar, and choose Document Properties. Chrome cannot show you this.

Your Flag: What software and version is listed as the PDF's Producer?

DEBRIEF · STAGE 1

A Joke That Became Permanent

Flag 1

(Unused)

The official IANA registry lists 418 as (Unused) and points to RFC 9110, which explains why:

"[RFC2324] was an April 1 RFC that lampooned the various ways HTTP was abused; one such abuse was the definition of an application-specific 418 status code, which has been deployed as a joke often enough for the code to be unusable for any future use."

The lesson: a registry is a primary source. Instead of trusting what people say online, you went to the organization that actually decides — and got a better answer than the memes.

DEBRIEF · STAGE 2

Dead Domain, Living Memory

Flag 2

Palo Alto Research Center

RFC 2324 lists the author as Larry Masinter at masinter@parc.xerox.com. Xerox PARC invented the laser printer, the graphical desktop, and Ethernet. That domain has been dead for years — and the site is still perfectly readable.

The lesson: taking something offline does not remove it. Anything a company published, an employee posted, or a student put on a profile may still be sitting in an archive that nobody can edit. Assume the internet keeps a copy.

DEBRIEF · STAGE 3

Files Talk Too Much

Flag 3

Acrobat Distiller 8.1.0 (Windows)

Nothing on the visible page said any of this:

Title:    HTTP: how we got here and where we should go

Author:   Larry Masinter

Creator:  Acrobat PDFMaker 8.1 for PowerPoint

Producer: Acrobat Distiller 8.1.0 (Windows)

Created:  2007-12-03

Read that like an attacker. In four lines the file gave up:

  • ►Who wrote it, by name.
  • ►That the "PDF" was really a PowerPoint deck.
  • ►The operating system it was built on: Windows.
  • ►An exact software version — and old versions have published vulnerabilities anyone can look up.

The lesson: this is called version disclosure, and it is a real finding on real penetration tests. Every document an organization posts is a small confession about the software it runs.

What You Just Did

Stage 1

Primary sources

Went to the authority that decides, instead of trusting secondhand claims.

Stage 2

Historical archives

Recovered a site that has not existed for years, because deleting is not erasing.

Stage 3

File metadata

Pulled software, platform, and authorship out of a file's hidden properties.

You did not break into anything. Every record you touched was published deliberately by someone who never imagined a stranger stringing them together years later. That is what makes OSINT powerful — and what makes it worth thinking about before you post.

Before You Try This Yourself

Every source in this lab was a professional public record: a standards document, a defunct company's homepage, and a conference talk the author posted himself. That boundary was chosen on purpose.

Reasonable

Researching your own footprint, or an organization you have written permission to test.

Not reasonable

Compiling information about a classmate, an ex, or any private individual. Legal to read does not mean acceptable to collect.

The techniques are identical either way. Authorization is the entire difference, and it is the part that keeps you employable.
