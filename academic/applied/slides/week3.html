What are Indicators of Compromise (IoCs)?

IoCs are the digital "bread crumbs" or forensic evidence that indicate a potential security breach has occurred on a system or network.

Why They Matter

  • Detection: Help security tools and analysts identify ongoing attacks.
  • Response: Provide specific data to search for during an incident (e.g., "scan all PCs for this file hash").
  • Prevention: Can be fed into firewalls, proxies, and EDRs to block future attacks.

Common Categories

  • Network-based: Unusual traffic, connections to known bad IPs, strange DNS requests.
  • Host-based: Suspicious files (by name or hash), new registry keys, unexpected running processes.
  • Behavioral: A user account logging in at 3 AM, mass file deletions.

Ransomware

Malware that takes over a computer and demands a ransom, often by encrypting files (crypto malware).

Indicators of Compromise (IoCs)

  • Command & Control (C&C) traffic
  • Abnormal use of legitimate tools (e.g., PowerShell)
  • Lateral movement attempts
  • Mass file encryption
  • Ransom notes on screen
  • Large data exfiltration

Mitigation

  • Effective, isolated backups are the #1 defense.
  • Anti-ransomware & EDR tools
  • User training against phishing
  • Network segmentation
  • Have a pre-defined response plan.

🚨 Real-World Example (2024): Black Basta

The Black Basta ransomware group targeted the Ascension health system, one of the largest in the U.S. The attack disrupted clinical operations across 140 hospitals, forcing them to divert ambulances and revert to paper records, highlighting the critical threat to public safety.

Trojans (Trojan Horses)

Malware disguised as legitimate software. Relies on users running it to infect a system.

Indicators of Compromise (IoCs)

  • Signatures of known malicious files
  • C&C hostnames and IP addresses
  • Unexpected new files or folders
  • Unusual network traffic from a new "app"
  • Remote Access Trojans (RATs) provide full remote control.

Mitigation

  • Security awareness training (don't download untrusted software!)
  • Application whitelisting/control
  • Antimalware/EDR tools
  • Regularly review installed programs.

🎭 Real-World Example: Triada Trojan

The Triada Trojan was often bundled with modified versions of popular apps like WhatsApp. Once installed, it gathered device info, registered with a C&C server, and then downloaded further malicious modules to perform actions like displaying ads or signing the user up for paid subscriptions without their consent.

Worms

Self-replicating malware that spreads automatically without user interaction, typically by exploiting vulnerabilities in network services.

Indicators of Compromise (IoCs)

  • High volume of network scanning
  • Unusual traffic patterns between internal systems
  • Downloads from remote systems
  • Use of system commands for injection
  • Signs of a botnet (C&C traffic)

Mitigation

  • Network segmentation and firewalls are critical to contain spread.
  • Timely vulnerability patching
  • Intrusion Prevention Systems (IPS)
  • Disabling unnecessary services

🍓 Real-World Example: Raspberry Robin

The Raspberry Robin worm initially spread via infected USB drives. Once active, it uses built-in Windows tools to move laterally across networks. It's often used as an initial access tool by ransomware gangs, dropping other malware once it has established a foothold.

Viruses

Malicious programs that attach to legitimate files or programs and require user action to activate and spread. Unlike worms, they don't self-propagate across networks.

Types of Viruses

  • Memory-resident: Stays in RAM.
  • Boot Sector: Infects the master boot record.
  • Macro: Lives in documents (e.g., Word, Excel).
  • Fileless: Lives only in memory, never writing to disk.

Mitigation

  • Antimalware/Antivirus software
  • User awareness (don't open strange attachments!)
  • Patching browsers and plugins
  • Best Practice: Wipe and reimage infected machines.

👻 Real-World Example: Fileless Malware

An attacker sends a phishing email with a link. The user clicks, exploiting a browser vulnerability to run a script (like PowerShell) directly in memory. This script can then download other malware or steal data without ever writing a traditional malicious file to the hard drive, making it very difficult for signature-based antivirus to detect.

Spyware & Keyloggers

🕵️ Spyware

Malware designed to obtain information about an individual, organization, or system.

⌨️ Keyloggers

A type of spyware that captures keystrokes, mouse input, and other user actions.

Indicators & Mitigation

  • IoCs: Unexpected network traffic (data exfiltration), new processes disguised as system processes, browser injection attacks.
  • Mitigation: Anti-spyware/antimalware tools, user awareness, controlling software installation.
  • For Keyloggers: Multi-Factor Authentication (MFA) is a crucial defense.

📱 Real-World Example: Pegasus Spyware

Developed by the NSO Group, Pegasus is a powerful "zero-click" spyware that can infect iOS and Android devices without any user interaction. It can harvest texts, track calls, collect passwords, and activate the phone's camera and microphone, and is used for espionage against journalists, activists, and political figures.

Rootkits & Logic Bombs

👻 Rootkits

Malware designed to gain administrative-level control over a system while hiding its presence.

💣 Logic Bombs

Malicious code that lies dormant until a specific condition is met (e.g., a certain date).

Detection & Mitigation

  • Rootkits: Detection is hard because the OS can't be trusted. Best detected by scanning from a trusted, external system. Removal almost always requires a full system wipe.
  • Logic Bombs: Very difficult to detect. Mitigation relies on secure coding practices, code reviews, and strict change control processes.

🏧 Real-World Example: ATM Rootkit

Attackers have used rootkits on ATMs. The rootkit hides its presence and allows attackers to issue commands (often via a special card or code) to make the machine dispense cash on demand, a technique known as "jackpotting."

Bloatware

Unwanted applications pre-installed on systems by manufacturers or bundled with other software. Not usually malicious, but creates security risks.

The Problem with Bloatware

  • Wastes Resources
  • Increases Attack Surface
  • Privacy Concerns

Mitigation

  • Best Practice: Wipe new devices and install a clean, standard corporate image.
  • Manually uninstall unwanted applications.
  • Be careful during software installation to uncheck bundled "offers."

Group Activity: Incident Response

Scenario

A small accounting firm reports that their receptionist's computer is suddenly very slow. Later that day, the receptionist can't open any client files—they all have a `.LOCKED` extension. A note on the desktop demands a Bitcoin payment. Soon after, the main file server becomes inaccessible to everyone. Network monitoring tools show the receptionist's PC scanning the internal network and making strange connections to an IP address in Eastern Europe, `91.198.174.192`.

Your Task (10 minutes)

  • Identify the Malware: What specific type(s) of malware are likely involved in this attack? Explain the role of each.
  • List the IoCs: What are the specific Indicators of Compromise mentioned in the scenario?
  • Propose a Response: What are the immediate first three steps the firm should take to mitigate the damage?
  • Recommend Prevention: What are two key preventative measures that could have stopped this attack?

Malware Analysis: Sandboxes

Analysts use safe, isolated environments (sandboxes) to observe malware behavior without risking a real system.

Online Sandboxes (Easy & Fast)

  • VirusTotal: Upload a file/URL to scan it against dozens of AV engines and see community reports.
  • ANY.RUN: An interactive online sandbox to detonate malware and watch its actions in real-time.

Local Sandboxes (Powerful & Private)

  • Cuckoo Sandbox: An open-source, automated sandbox you set up yourself for detailed reports on file activity, network traffic, and API calls.

Web-Based Analysis Tools

Beyond sandboxes, these public tools provide valuable threat intelligence and context.

Device & Service Discovery

  • Shodan.io: A search engine for internet-connected devices. Used to find vulnerable systems, exposed services, and even malware C&C servers.

URL & IP Reputation

  • URLScan.io: Scans a website and provides a detailed report of all resources, connections, and technologies used. Excellent for analyzing phishing links safely.
  • AbuseIPDB: A database of IP addresses that have been reported for malicious activity. Check if an IoC is a known bad actor.

Key Exam Points

🦠 Malware Distinctions

Know the key difference: A Trojan needs a user to run it. A Worm spreads by itself. A Virus attaches to files and needs user action to spread.

🔍 Common IoCs

Be ready to identify C&C traffic, unexpected file encryption, lateral movement, data exfiltration, and unusual use of system tools (PowerShell, cmd.exe).

👻 Stealthy Malware

Rootkits and Fileless Viruses are designed for stealth. Detection often requires out-of-band analysis (offline scans) or behavioral monitoring.

🛡️ Core Mitigation Strategy

For most significant malware infections (ransomware, rootkits), the safest mitigation is to wipe the system and restore from a known-good backup or image.

Chapter Summary

🔬 Know Your Malware

Each malware type has unique characteristics. Understanding if it self-propagates (worm), requires a user (Trojan/virus), encrypts files (ransomware), or hides itself (rootkit) is key to analysis.

🎯 Indicators are Clues

Recognizing IoCs like strange network traffic, new files, or encrypted data allows you to identify and respond to an attack quickly.

🛡️ Defense in Depth

A combination of technical controls (antimalware, firewalls, patching) and human controls (user awareness) is the most effective defense.

🚨 Bottom Line

When an infection occurs, assume the worst. The most reliable path to a clean system is often to wipe and rebuild, not to attempt a risky and uncertain cleaning process.
