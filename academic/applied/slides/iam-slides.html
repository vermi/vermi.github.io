What is Identity?

Identities are the sets of claims made about a subject (person, application, device, system, or organization).

📋 Attributes

Information about the subject that can change over time.

  • Name, job title
  • Address, department
  • Phone number, email

🧬 Traits

Characteristics that are inherent to the subject.

  • Height, eye color
  • Place of birth
  • Fingerprint pattern

Ways to Claim an Identity

👤 Usernames

Most common way to claim identity. Not an authentication factor by itself.

📜 Certificates

Digital certificates stored on systems or security tokens. Used for systems and individuals.

🔑 Tokens

Physical devices that generate codes, plug in via USB, or connect via Bluetooth.

🔐 SSH Keys

Cryptographic key pairs that replace username/password authentication.

💳 Smartcards

Embedded chips (contactless or physical). Can generate key pairs on the card itself.

Real-World: Lost Key Pairs

🚨 The Danger of Exposed Keys

Uploading private keys to public code repositories (like GitHub) is a common security incident.

Poor Practices: Using blank passphrases for SSH keys, storing keys in insecure locations.

Cloud Monitoring: AWS, Azure, and GCP actively monitor for key exposures and exploits that follow.

Smartcard Security: Well-designed smartcards generate key pairs ON the card to prevent copies.

Authentication vs Authorization

🔐 Authentication

Proves WHO you are

Verifies the identity belongs to the person claiming it.

✅ Authorization

Verifies WHAT you can access

Determines permissions and rights based on your identity.

Combined: First verify who you are (authentication), then allow access based on what you're authorized to use (authorization).

The AAA Model

Authentication

Users must first prove their identity, typically with username and password (or other factors).

Authorization

System determines what actions the authenticated user is permitted to perform.

Accounting

Tracks resource utilization: time, bandwidth, CPU usage, actions performed.

Key Protocols: RADIUS and TACACS+ are commonly associated with AAA systems.

EAP - Extensible Authentication Protocol

An authentication framework commonly used for wireless networks.

Common EAP Methods:

  • EAP-TLS: Uses certificates (most secure)
  • EAP-TTLS: Tunneled TLS
  • PEAP: Protected EAP (Microsoft)
  • LEAP: Lightweight EAP (Cisco, deprecated)

Key Points:

  • Framework, not a single protocol
  • Primary use: Wireless authentication
  • Works with 802.1X
  • Multiple implementations exist

CHAP - Challenge Handshake Authentication Protocol

Uses an encrypted challenge and three-way handshake to send credentials securely.

1️⃣

Challenge

Server sends a random challenge to client

2️⃣

Response

Client responds with username and hashed password + challenge

3️⃣

Accept/Reject

Server verifies and accepts or rejects

More secure than PAP (Password Authentication Protocol), which sends passwords in cleartext.

802.1X - Network Access Control

IEEE standard for port-based network access control (NAC).

💻 Supplicant

The client device requesting network access

🔌 Authenticator

Network switch, AP, or wireless controller

🖥️ Auth Server

RADIUS server that validates credentials

Flow: Supplicant → (EAP) → Authenticator → (RADIUS) → Auth Server → (LDAP) → Directory

RADIUS

Remote Authentication Dial-In User Service

Key Characteristics:

  • Client-server model
  • Uses UDP (or TCP)
  • Provides AAA services
  • Common for network devices, wireless

⚠️ Security Consideration:

Passwords obfuscated with shared secret + MD5 hash (not strong). Traffic should be encrypted with IPSec tunnels.

TACACS+

Terminal Access Controller Access Control System Plus (Cisco)

✅ Advantages over RADIUS:

  • Uses TCP (more reliable)
  • Full packet encryption
  • Granular command controls
  • Separates AAA functions

Common Use Cases:

  • Network device administration
  • Router/switch management
  • Per-command authorization

RADIUS vs TACACS+: RADIUS combines auth+authz; TACACS+ separates all three AAA functions.

Kerberos Authentication

A protocol for authenticating service requests between trusted hosts across untrusted networks.

Primary

Typically the username

Instance

Differentiates similar primaries

Realms

Groups of users (trust boundaries)

Key Components:

  • KDC: Key Distribution Center
  • TGT: Ticket-Granting Ticket
  • TGS: Ticket-Granting Service

Kerberos Authentication Flow

1️⃣

Client → Authentication Server

Client requests a Ticket-Granting Ticket (TGT)

2️⃣

Auth Server → Client

Server validates credentials, returns TGT (encrypted with TGS secret key)

3️⃣

Client → TGS

Client sends TGT + requested service name to get a service ticket

4️⃣

Client → Service Server

Client presents service ticket to access the service

Single Sign-On (SSO)

Log in once, access multiple systems or services without re-authenticating.

✅ Advantages:

  • Simplified user experience
  • Reduced password fatigue
  • Fewer help desk calls
  • Centralized authentication

⚠️ Trade-offs:

  • Single point of failure
  • If SSO is compromised, all systems are at risk
  • May need additional auth for high-security systems

Example: Log into Gmail → automatically authenticated to YouTube, Google Drive, etc.

LDAP - Lightweight Directory Access Protocol

A directory service that provides hierarchically organized information about an organization.

Directory Structure:

  • DC: Domain Component (e.g., dc=example,dc=com)
  • OU: Organizational Unit (e.g., ou=security)
  • CN: Common Name (e.g., cn=johndoe)
  • DN: Distinguished Name (full path)

Common Uses:

  • Email/contact directories
  • Authentication backend
  • Active Directory integration
  • SSO infrastructure

SAML - Security Assertion Markup Language

XML-based open standard for exchanging authentication and authorization information.

Principal

The user requesting access

Identity Provider (IdP)

Authenticates the user

Service Provider (SP)

Provides the service/resource

Primary Use: Web-based SSO between identity providers and service providers. Common in federated environments.

OAuth - Open Authorization

Open standard for authorization (not authentication!) - allows limited access without sharing credentials.

How OAuth Works:

  1. App requests access to your data (e.g., Google Drive)
  2. You're redirected to authorize specific permissions
  3. You grant access without sharing your password
  4. App receives an access token with limited scope

Example: "Allow Zoom to access your Google Calendar?" - OAuth handles the authorization.

OpenID (Connect)

Open standard for decentralized authentication - "Log in with Google/Microsoft/etc."

Identity Providers (IdPs):

  • Google
  • Microsoft
  • Amazon
  • Facebook

How It Works:

  1. Relying Party redirects to IdP
  2. User authenticates with IdP
  3. IdP returns assertion
  4. User logged in via OpenID

Comparing SSO Technologies

Technology Purpose Format Use Case
SAML Authentication + Authorization XML Enterprise SSO, Federation
OAuth Authorization only JSON API access, delegated auth
OpenID Authentication only JSON "Login with..." buttons
LDAP Directory services Binary Backend identity store

Federation

Allows users authenticated by one organization to access resources at partner organizations.

Key Terms:

  • Principal: The user
  • Identity Provider (IdP): Authenticates users
  • Service Provider (SP): Provides services
  • Relying Party (RP): Trusts the IdP

Attestation:

Formal verification that something is true. The IdP attests that a user is who they claim to be.

Interoperability: SAML, OAuth, and OpenID enable standards-based federation between different systems.

Password Best Practices

NIST SP 800-63B provides modern guidelines for password security.

✅ NIST Recommends:

  • Emphasize length over complexity
  • Allow all ASCII/Unicode characters
  • Allow paste into password fields
  • Check against breached password lists
  • Eliminate password hints

❌ NIST Discourages:

  • Mandatory special characters
  • Frequent password rotation
  • Security questions
  • SMS-only 2FA

Password Configuration Settings

📏 Length

Minimum characters required. Best defense against brute-force.

🔤 Complexity

Requires mix of uppercase, lowercase, numbers, symbols.

🔄 Reuse

Prevents using previous X passwords again.

⏰ Expiration

Maximum password age before forced change.

📅 Age (Minimum)

Prevents rapid cycling through passwords.

🔒 Lockout

Account locks after X failed attempts.

Password Managers

Tools that help create, store, and manage passwords securely.

Third-Party Managers:

  • 1Password
  • Bitwarden
  • LastPass
  • Dashlane

Built-in Options:

  • Windows Credential Manager
  • Apple Keychain (iCloud sync)
  • Browser-based managers

Benefits: Reduces password reuse, enables complex unique passwords, secure encrypted storage.

Real-World: LastPass Breach (2022-2023)

🚨 What Happened:

  • First incident led to second, more severe breach
  • Customer vault backups were stolen
  • MFA seeds and phone numbers exposed
  • Attackers obtained encrypted vaults

Lessons Learned:

  • Password managers are targets themselves
  • Strong master passwords are critical
  • Consider local-only or self-hosted options for high security
  • Have a breach response plan for credential rotation

Passwordless Authentication

Authentication without passwords using "something you have" or "something you are."

🔑 Security Keys

  • Hardware devices (YubiKey, Titan)
  • Support FIDO2, U2F protocols
  • USB, NFC, or Bluetooth
  • Public key cryptography

📱 Other Methods:

  • Biometrics (fingerprint, face)
  • Magic links (email)
  • Authenticator apps
  • Passkeys (FIDO2)

FIDO2: Open standard supporting W3C Web Authentication and Client to Authenticator Protocol (CTAP).

Multifactor Authentication (MFA)

Requires two or more authentication factors from different categories.

🧠

Something You Know

Passwords, PINs, security questions

🔑

Something You Have

Tokens, smartcards, phones

👤

Something You Are

Biometrics (fingerprint, face)

📍

Somewhere You Are

GPS, network location

One-Time Passwords (OTP)

Passwords valid for only one use or one time period.

⏰ TOTP (Time-Based)

  • Uses current time in algorithm
  • Valid for set period (30-60 seconds)
  • Google Authenticator, Authy
  • Requires synced clocks

🔢 HOTP (HMAC-Based)

  • Uses counter value
  • Valid until used
  • Button-press tokens
  • Counter syncs on use

SMS OTP & Push Notifications

📱 SMS OTP

Code sent via text message

Vulnerabilities: SIM swapping, SS7 attacks, VoIP interception

🔔 Push Notifications

Approve/deny on your phone

Risk: "MFA fatigue" attacks - users approve to stop notifications

🚨 Attacking OTPs:

  • TOTP theft via phishing (must use immediately)
  • SIM cloning/swapping for SMS
  • MFA bombing/fatigue attacks
  • Real-time phishing proxies (evilginx)

Evaluating Biometrics

Type I Error - False Rejection Rate (FRR)

Legitimate user is rejected. Frustrates users.

Type II Error - False Acceptance Rate (FAR)

Impostor is accepted. Security risk!

📊 Receiver Operating Characteristic (ROC)

Graph comparing FRR vs FAR. Helps find optimal sensitivity setting.

Trade-off: Decreasing FRR typically increases FAR, and vice versa. Balance security vs. usability.

Account Types

👤 User Accounts

Standard accounts for everyday users. Limited privileges.

👑 Privileged/Admin

Root, Administrator, wheel group. Full system access.

👥 Shared/Generic

Multiple users share one account. Generally discouraged.

🎫 Guest Accounts

Temporary, very limited privileges. Minimal tracking.

⚙️ Service Accounts

Used by applications/services. Should not allow interactive login.

Provisioning Accounts

The process of creating an account and assigning resources, permissions, and attributes.

🪪 Identity Proofing

Verifying the person is who they claim to be (government ID, personal info verification).

📋 Onboarding Tasks

  • Add to appropriate groups
  • Assign permissions based on role
  • Provide security training
  • Configure MFA

Permission Management

✅ Least Privilege

Grant only the minimum permissions needed to perform a job function.

⚠️ Permission Creep

Users accumulate permissions over time as roles change. Creates excessive access.

Common Mistake:

"Give the new hire the same permissions as the person they're replacing." If that person had permission creep, the new hire inherits the problem.

Deprovisioning Accounts

The process of terminating an account - removing access, permissions, and associated data.

✅ Best Practice: Delete

  • Completely removes account
  • Prevents reactivation attacks
  • Removes attack surface

⚠️ Disable Only?

  • May be required for audit trails
  • Risk: Improperly re-enabled later
  • Dormant accounts are targets

Privileged Access Management (PAM)

Tools and processes for managing administrative and privileged accounts.

⏱️ Just-In-Time (JIT)

Permissions granted only when needed, revoked when task is complete.

🔐 Password Vaulting

Secure storage for privileged credentials. Check-out system with logging.

⏳ Ephemeral Accounts

Temporary accounts with limited lifespan. Auto-expire after use.

Mandatory Access Control (MAC)

The operating system enforces access control set by security administrators.

Key Characteristics:

  • Users cannot change permissions
  • Centrally controlled by admins
  • Uses labels/classifications
  • Highest security level

Examples:

  • SELinux
  • Windows Mandatory Integrity Control (MIC)
  • Military/government systems

Discretionary Access Control (DAC)

Owners of objects can delegate rights and permissions to others at their discretion.

Key Characteristics:

  • File/folder owners control access
  • Most common in personal computers
  • Flexible but less secure
  • Users can share freely

Examples:

  • Standard Linux file permissions
  • Windows NTFS (without MIC)
  • macOS file sharing

Role-Based Access Control (RBAC)

Access based on roles assigned to users. Roles have associated permissions.

Three Primary Rules:

  1. Role Assignment: Users can only use permissions of assigned roles
  2. Role Authorization: User's active role must be authorized for them
  3. Permission Authorization: Users can only use permissions their active role allows

Example: "Cashier" role vs "Database Administrator" role - different permissions for different job functions.

Rule-Based & Attribute-Based Access Control

📋 Rule-Based (RuBAC)

Access controlled by a set of rules or ACLs.

  • Firewall rules
  • Router ACLs
  • If-then conditions

🏷️ Attribute-Based (ABAC)

Policies driven by user attributes.

  • Very flexible
  • Complex to manage
  • Good for enterprise apps
  • Microservices & APIs

ABAC Example: Allow access if user.department="Finance" AND user.clearance="Secret" AND time.hour > 9 AND time.hour < 17

Additional Access Controls

⏰ Time-of-Day Restrictions

  • Limit when users can log in
  • Configured in Active Directory
  • Prevents off-hours abuse
  • Useful for shift workers

🔒 Least Privilege

  • Minimum permissions needed
  • Core security principle
  • Reduces attack surface
  • Limits blast radius of compromise

Chapter Summary

🆔 Identity is Foundational

Identities are claimed through usernames, certificates, tokens, SSH keys, or smartcards, then proven through authentication.

🔐 SSO & Federation Enable Scale

LDAP, SAML, OAuth, and OpenID allow single sign-on and cross-organization federation.

🔑 MFA is Essential

Multiple factors (know, have, are, location) protect against credential theft. TOTP/HOTP and biometrics are common implementations.

🛡️ Access Control Protects Resources

MAC, DAC, RBAC, Rule-based, and ABAC provide different approaches. PAM manages privileged accounts with JIT and vaulting.

Exam Essentials

Know the four MFA factors: Something you know, have, are, and somewhere you are.

Understand SSO technologies: LDAP (directory), SAML (auth+authz), OAuth (authorization), OpenID (authentication).

Know access control schemes: MAC (system enforced), DAC (owner controlled), RBAC (roles), ABAC (attributes).

Understand account lifecycle: Provisioning, identity proofing, permission management, deprovisioning.

Know PAM concepts: Just-in-time permissions, password vaulting, ephemeral accounts.
